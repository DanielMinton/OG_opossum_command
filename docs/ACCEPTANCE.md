**Definition of done** (spec §18): a real workflow runs from a tile; status is unmistakable; it can be cancelled; history is redacted; recovery is predictable; no admin install. Rows 1, 4, 5, 11 and 13 cover the parts, and M7 is the end-to-end check.

## Manual checks

Do these after the phase 7 install, using your real data folder. Each takes a minute or two.

- **M1 · Standard user.** Start the installed OG Opossum Command Central (`%LOCALAPPDATA%\Programs\OG_opossum_command\OG_opossum_command.exe`, or a shortcut if the installer made one). No UAC prompt appears. Run **Focus Mode** (or any tile). It completes, and Windows never asks for admin rights.
- **M2 · UI close.** Start a workflow (for example **Start Workday**). While it runs, close the window with ✕. The tray icon stays. Open it again: the run has continued or finished, and History shows it. Then tray menu → **Quit**: the app exits, and a run still active is shown as Cancelled the next time you start the app.
- **M3 · Offline.** Turn Wi-Fi off (or unplug the network). Run a local tile (open a folder, **Hello Script** in Personal): it completes. A web page tile still hands the URL to the browser, which shows its own offline page. The Today panel says the calendar is stale or unavailable rather than failing. Turn the network back on.
- **M4 · Update.** Before installing a new version, note your tiles and the last few History rows. Install the new version (phase 7 script). Start it: the same tiles, profiles, settings (hotkey, quiet mode) and History are all there.
- **M5 · Accessibility.**
  1. *Keyboard only:* press Ctrl+Alt+Space, type part of a workflow name, use the arrow keys, then Esc. In the main window, Tab reaches every tile, Refresh, Cancel, the footer buttons and the lists, and a thick highlight ring shows where focus is. Alt+F focuses the profile box, Alt+P opens the palette, Alt+D/H/S switch views. Win+B, arrow to the app's tray icon, Enter: the dashboard opens.
  2. *Narrator* (Ctrl+Win+Enter): tiles read "Run <name>", empty tiles read "Empty slot. Add a workflow file to …". Starting a tile announces "Queued …" and the progress line. Recent-runs rows read "workflow, status, time, result". Palette arrows announce the selected workflow. Turn Narrator off.
  3. *High contrast:* Settings → Accessibility → Contrast themes → pick one. All text, borders and focus rings stay visible. Switch back.
  4. *Text size:* Settings → Accessibility → Text size → 150%, then quit and restart the app. **Does the app's text get bigger?** If it does not, tell me: the scaling then needs to read the Text size setting directly (a small change in `Accessibility/FontScale.cs`). Either way, nothing should be clipped, the dashboard should scroll, and Cancel should stay visible while a run is active. Set the slider back afterwards.
  5. *Reduced motion:* nothing in the app animates, so there is nothing to turn off. Confirm that nothing slides or fades.
- **M6 · Target environment.** After the phase 7 install, confirm that the app starts from `%LOCALAPPDATA%\Programs\OG_opossum_command`, with no SmartScreen or AppLocker block. If something is blocked, stop; do not work around it.
- **M7 · Definition of done.** Run your real **Start Workday** tile. Watch the status, Cancel it once (it says Cancelled, and nothing it launched keeps running), run it again to completion, open History and check that the output shows no secrets.

### Phase 8-9 (exports and alerts, 0.2.0)

Do these after installing 0.2.0. The flows are yours to build (docs/POWER_AUTOMATE_FLOW.md); each check says what to look at before and after.

- **M8 · status.json.** Start the app with your work OneDrive signed in. Within a minute, `%OneDriveCommercial%\OG_opossum_command\status.json` exists, and Settings → **Exports** → Work says "status.json: last written …". Open the file in Notepad: `profile` is `"Work"`, `generatedAt` is a few seconds old, and there are no file paths, links, or step output in it. Run any Work tile; within a few seconds of it finishing (at most once every 30 s), `generatedAt` moves on and `completedToday` goes up by one. No `.ogoc-tmp` file is left in the folder.
- **M9 · Folder missing.** Pause OneDrive sync, or temporarily rename the `OG_opossum_command` folder (with the app quit), then start the app. Settings → Exports says the folder is missing (or that it created `OG_opossum_command` inside your existing OneDrive). The app never creates the OneDrive root itself. Put things back afterwards.
- **M10 · Alert outbox.** With the alerts flow off, make a Work workflow fail (for example a copy of one with a wrong `.exe` path). Exactly one file appears in `OG_opossum_command\outbox\`, named `<date>-<time>-<32 hex>.json`, with `"event": "run.failed"`. Run it again right away: no second file appears (one per workflow and event per 30 minutes). Turn Quiet mode **on** and repeat after 30 minutes: a file still appears, because quiet hours belong to the flow. Settings → Exports shows "last alert (run.failed)".
- **M11 · Alerts flow.** Turn the alerts flow on. The next alert file reaches Teams as one message from Flow bot and then disappears from `outbox\`. During your quiet hours, the message waits until 07:00.
- **M12 · Morning Briefing.** Run the briefing flow manually (Test → Manually). Its Teams message matches Settings → Exports and the dashboard (needs attention, failures, completed today). Quit the app, wait 30 minutes, and run it again: it says the app hasn't updated.
- **M13 · Carryovers.** Run the carryovers flow manually in the afternoon. The Today panel shows "No carryovers for today (the file is for …)" today, not the items. The next working day, start the app (or press Refresh): **Carryovers from yesterday** lists the items, with Narrator reading each title and its details. Edit `tomorrow.json` by hand to add an unknown property: Refresh shows "not in the expected shape" and no items, and the app keeps working. Restore it.
- **M14 · Personal stays off.** Settings → Exports → Personal says everything is off ("Off by default for the Personal profile"). No file appears anywhere in your personal OneDrive. If you ever enable Personal exports, its `exports.folder` must be outside the work OneDrive. Pointing it into the work OneDrive makes the Personal `profile.json` an error, and Personal then has no `m365.*` actions and no exports.
- **M15 · New look and the wheel.** The window has the Windows 11 look and follows Settings → Personalization → Colors (light, dark, accent). With a high contrast theme on, every text and focus ring is readable. Click the profile picker once (so it has focus), close it, then roll the mouse wheel over it: the profile does **not** change. Roll the wheel over Recent runs: the dashboard scrolls.
